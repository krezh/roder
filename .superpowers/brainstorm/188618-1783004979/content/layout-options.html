Two ways to get an ArgoCD-style visual tree

Both use the same recursive data we already fetch from the backend — they differ in how much new rendering machinery they need. A true ArgoCD clone (free-form canvas, drag/pan/zoom, curved edge routing via a layout engine) is a much bigger lift than either of these — shown at the bottom for reference, not proposed as in-scope.

Same shape as today's list (indent = ownership), each row becomes a small card: icon, colored left-border + status dot on owners, kind badge, name, namespace. No pan/zoom, no layout engine — pure CSS on the tree we already render.

Each depth becomes its own column (root left, deeper = further right), thin SVG lines connect a card to its children — the "flows left to right" look ArgoCD is known for. Needs a small layout pass (stack cards per column, measure positions, draw lines) and horizontal scroll for deep/wide trees. No pan/zoom or drag.

For reference, not proposed: the actual ArgoCD tree is a free-form force/dagre-style graph — nodes can be dragged, the canvas pans and zooms, edges curve around obstacles. Building that means a real graph-layout engine plus a pan/zoom canvas (SVG or a JS graph library) — a substantially bigger project than either option above. Worth doing later if the columned version isn't enough, not a good place to start.
